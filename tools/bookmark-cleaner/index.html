Chrome Bookmark Cleaner

Remove duplicate bookmarks, dead links, and empty folders from exported bookmarks.html. Zero server uploads — all processing happens directly in your browser.

What it does

Parses exported Netscape Bookmark HTML files from Chrome, Firefox, Safari, or Edge, and strips duplicate URLs while maintaining folder structure integrity. Sanitizes messy bookmark collections to reduce clutter and speed up bookmark searches across desktop browsers.

Common use cases

  • Browser Bookmark Deduplication: Remove redundant bookmarks accumulated across multiple computers and browser sync profiles.
  • Security Audit of Exported Bookmarks: Strip hazardous bookmarklets and obsolete javascript: URLs from your browser export files.
  • HTML Bookmark File Minification: Clean legacy Netscape bookmark backups to reduce file size before importing into fresh browser installations.

How to use

  1. Export your browser bookmarks as an HTML file from Chrome or Firefox bookmark manager.
  2. Drop the exported bookmarks.html file into the cleaner drop zone.
  3. The parser scans links and removes duplicate URL entries while preserving folder hierarchies.
  4. Download your cleaned bookmarks.html file and import it back into your browser.

Limits & Considerations

Deduplicates by matching exact canonical URL strings. Does not check remote network connectivity for HTTP 404 broken links.

Frequently Asked Questions

What bookmark file formats are accepted?

The cleaner supports standard HTML bookmark backup files (NETSCAPE-Bookmark-file-1 format) exported by Chrome, Firefox, Safari, and Edge.

Does the cleaner delete folder hierarchies?

No. Your folder categories and organizational structure are retained while duplicate links inside those folders are pruned.

How does it protect against malicious bookmarklets?

The cleaner filters out javascript:, data:, and file: URI protocols, preserving only legitimate http:// and https:// web addresses.

Privacy & Security

Your browsing history and saved bookmarks are sensitive. All parsing is executed in local browser memory with zero external network requests.
